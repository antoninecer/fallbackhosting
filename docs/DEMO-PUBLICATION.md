# Authenticated demo publication — FH-0027

The maintenance page adds a fixed-app prepare, preview, publish and rollback workflow. The source origin, contact text, destination and backup node are immutable operator configuration, never submitted through a web form. This is the existing single-page cafe adapter; it does not mirror arbitrary sites or back up databases/controllers.

A separate private Unix socket authenticates the actual PHP peer UID and administrator identity. Session, exact Origin and CSRF validation remain in PHP. The worker runs as the existing technical identity with NoNewPrivileges, no capabilities, immutable root-owned code/policy and write access only to its private working directory and this demo's static tree. It uses the existing pinned SSH transport directly as the identity owner; PHP and the maintenance health worker receive no keys or SSH/Docker commands. It cannot call sudo. Network/SSH access is inherent to the backup worker; this is not a new tenant isolation guarantee.

Prepare exports one fixed public page and approved assets, sanitizes dynamic actions, creates an archive, uploads it, independently downloads it, checks its hash and restores it into a new isolated directory. Only verified copies become READY and available to the authenticated preview. Preparation leaves the published current pointer unchanged. Preview serves only HTML/CSS/WebP from a validated release ID under a fixed root, checks file hashes, requires a session, disables scripting/forms with CSP and rewrites assets to authenticated preview routes.

Publishing is a separate revision-bound action after preparation. It revalidates integrity, verified backup status and the previous current target, then atomically switches only the demo current pointer. Previous releases remain. The rollback action verifies and restores the previous release. Stale requests, unknown fields/operations, wrong peer/actor/app and concurrent current changes are rejected. A service restart during PREPARING/PUBLISHING/ROLLING_BACK marks NEEDS_REVIEW and never replays the operation automatically. An administrator reconciles the journal and actual pointer privately before recovery; the UI cannot clear this gate.

The health/maintenance worker stays separate. Existing Nginx public serving requires neither publication service, PHP, SSH, controller nor backup repository. No Nginx configuration change is needed for this increment. A preparation failure cannot remove the existing published version. Status responses omit raw exceptions, paths, endpoints, credentials and archive content.

Live activation has separate checkpoint evidence; do not infer it from local tests.

Activation scope: new fallback-publication-demo.socket/service, root-owned /var/lib/fallback-publication-demo code/policy, its identity-owned runtime and write access to only /var/www/fallback-standby-demo plus releases directory; new immutable PHP release and existing release pointer switch with syntax-tested graceful FPM reload. Preserve original auth/inventory and unrelated configs. Freeze Git sources before activation; record private journal of previous PHP/static pointers, exact ownership and unit hashes, and protected canaries.

Operational rollback: stop/disable only the new publication units, restore the journaled PHP pointer and reload FPM after syntax validation. Restore the static pointer only if it is still the version this operation published; reject concurrent drift. Restore only journaled static parent-directory ownership. Keep snapshots, remote archives, private journals and runtime for investigation. Do not rerun an initial activation against existing targets. Individual in-app static publication rollback is exercised separately from full service activation rollback.
